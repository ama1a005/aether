# AETHER Intermediate Review Demo

## Current verified entry point (2026-10-21)

Use `./scripts/run_review_demo.ps1 -Mode mock_deterministic` for the verified
model-free demo. The launcher builds the UI and serves UI plus API at
`http://127.0.0.1:8000/?mode=mock_deterministic`. It refuses occupied port 8000;
identify and stop only your previous demo process before retrying. Logs are in
`.local/demo/`. It prints the backend PID and stop command.

All 12 cases passed clean/attack/rescue/induction HTTP checks (48 actions).
This explicit mock mode is **not** external MCP traffic or Qwen inference.
The real external WSO2 mode currently fails on host-to-container HTTP framing;
its launcher now requires a successful MCP handshake instead of assuming that
a running container is ready. Qwen-over-FHIR is unqualified and disabled in the UI.
See `docs/RELIABILITY_CHECKPOINT.md` for verification and remaining limits.

For the tested Windows Python 3.11 dependency set, install
`requirements-demo-lock.txt` into `.venv`, then `pip install --no-deps -e .`.
The lock records the current working environment; a fresh network install and
remote CI run have not been verified in this checkpoint.

## Primary external FHIR MCP mode

The intended review path is `real_fhir_mcp_deterministic`: official WSO2 FHIR MCP over Streamable HTTP, local HAPI FHIR R4, and deterministic AETHER agents.

```powershell
.\scripts\start_review_fhir_stack.ps1
.\scripts\run_review_demo.ps1 -Mode real_fhir_mcp_deterministic
```

Images must be pulled once; subsequent review execution is local. See `docs/EXTERNAL_MCP_INTEGRATION.md`. Mock mode is an explicit emergency fallback and never activates automatically.

## Execution modes

- **Live Qwen + real MCP** uses `.venv-demo-gpu`, pinned CUDA PyTorch, one fp16 GPU model, and the independent `aether-clinical-tools` MCP stdio subprocess. Failure returns HTTP 503; it never switches mode automatically.
- **Deterministic fallback** is the original review-safe fixture pipeline. It is executable, but it is not model inference or MCP protocol traffic.
- **Verified replay** reads committed deterministic artifacts and is not live execution.

The eight live tools are real MCP tools in `demo/mcp_server/server.py`. Their data are synthetic local fixtures; “real MCP” describes the protocol connection, not an external clinical system.

## Live setup

```powershell
py -3.11 -m venv .venv-demo-gpu
.\scripts\setup_demo_gpu.ps1
.\.venv-demo-gpu\Scripts\python.exe scripts\download_demo_model.py
.\.venv-demo-gpu\Scripts\python.exe scripts\qualify_demo_live.py
# Legacy stdio/Qwen qualification is separate from the current review launcher.
```

The download script is the only model-download step. Runtime loading pins `Qwen/Qwen2.5-0.5B-Instruct` revision `7ae557604adf67be50417f59c2c2f167def9a775` and uses `local_files_only=True`. Set `AETHER_DEMO_MODEL_CACHE` to use an external cache. Use `-Mode deterministic` until live qualification succeeds.

Dependencies are downloaded first into ignored `.local/wheelhouse`, hashed in `wheelhouse_manifest.json`, and only then installed offline. The pinned GPU build is `torch==2.8.0` from the official CUDA 12.6 index for CPython 3.11/Windows x86-64. The demo does not use torchvision or torchaudio.

For an already transferred wheelhouse:

```powershell
.\scripts\install_demo_wheelhouse.ps1 -Wheelhouse .local\wheelhouse
```

For a transferred model snapshot, set its exact directory and verify it before loading:

```powershell
$env:AETHER_DEMO_MODEL_PATH = "D:\trusted-transfer\qwen-snapshot"
.\.venv-demo-gpu\Scripts\python.exe scripts\verify_demo_model_cache.py
.\.venv-demo-gpu\Scripts\python.exe scripts\accept_demo_model.py
```

The demo is a removable localhost-only review layer over AETHER core contracts, tools, mediator serialization, message intervention, and committed research artifacts. It never reads or executes frozen validation/test splits.

## One-command startup

```powershell
.\scripts\run_review_demo.ps1
```

The script builds the frontend and serves it with the API on loopback at `http://127.0.0.1:8000`. No login, cloud service, API key, or real patient information is used. The default external-MCP mode requires a working WSO2 handshake; choose `-Mode mock_deterministic` explicitly for the model-free fixture demo.

## Provenance modes

- **LIVE EXECUTION** runs the deterministic review fixture through actual AETHER tool helpers, `MediatorMessage`, label semantics, and `CrossAgentInterventionRunner`.
- **REPLAY — VERIFIED PRECOMPUTED EXECUTION** loads bundles generated by `python -m demo.backend.generate_replays` using that same backend.
- **VERIFIED PRECOMPUTED EXPERIMENT** reads committed research artifacts without rerunning expensive studies.

The live review-safe path does not claim to be a fresh Qwen run. Pinned Qwen evidence appears in Research Evidence with its exact artifact provenance.

## Optional model preload

Open **System Status** and select **PRELOAD MODEL**. This attempts one singleton load of pinned Qwen2.5-0.5B from the existing local Hugging Face cache; it never downloads a model. The panel reports device, available system memory, process RSS, and either **Model Ready** or an explicit error. Preloading is not required for the deterministic live review path.
