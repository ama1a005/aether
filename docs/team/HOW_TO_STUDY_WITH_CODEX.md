# How to Study AETHER with Codex

Use Codex as a code-reading partner, never as a source of unexecuted results. Begin each session by naming one bounded concept and asking for answers grounded in exact repository paths. Useful prompts include:

- “Trace `recommendation_code` from case input to receiver output and cite every function.”
- “Quiz me on the difference between attack success, mediation recovery, and circuit faithfulness.”
- “Give me an oral-review question, wait for my answer, then correct it using the contracts.”
- “Compare this result manifest with the reproducibility fields required by `AGENTS.md`.”
- “Explain one failed run and identify which claims it rules out.”

For a complete member session, use: “I am `MEMBER_3_MECHANISTIC_INSTRUMENTATION`. Read the required project and member sources, teach the whole project first, then teach my responsibility in depth, quiz me with one question at a time, and do not omit negative results.” Replace the tag with the appropriate canonical member tag. For rehearsal, use: “Act as an intermediate-review panel. Ask me code, metric, limitation, and cross-member handoff questions; after each answer, cite the exact source that confirms or corrects it.”

For every answer, verify the referenced file and distinguish code behavior, test evidence, development results, and future work. Never ask Codex to invent plausible metrics, reconstruct missing raw output, or upgrade development evidence into validation. End a session by writing three statements in your own words: what the code guarantees, what an executed artifact supports, and what remains unknown.
