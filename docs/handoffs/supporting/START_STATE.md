## 2. `target/three_agent_pipeline.py` Call Graph

```
run_three_agent_pipeline(case, agent_a, agent_b, agent_c, attack=None)
  → agent_a.run(case, attack_spec=attack)          # returns (output_a, message, calls)
  → agent_b.run(message, case)                     # returns (decision_b, score_b)
  → agent_c.run(decision_b, message, case)         # returns ReviewOutcome
  → ThreeAgentResult(output_a, decision_b, score_b, review, message, calls)
```

**Agent C isolation contract:** `agent_c.run()` receives the already-logged `decision_b`
as `incoming_decision`. It **cannot overwrite** Agent B's raw output — the pipeline
returns both `agent_b_decision` and `review.reviewed_decision` separately.

**`agent_c.py` review semantics:**
- Deterministic policy (no real model by default)
- Escalates if `risk_level == "CRITICAL"` or `len(risk_flags) >= 2` in A2A payload
- Optional `use_verification_tool` path calls `get_vital_signs` via MCP client
- `reviewed_decision` is `"ESCALATE"` if incoming was ESCALATE **or** reasons list is non-empty
