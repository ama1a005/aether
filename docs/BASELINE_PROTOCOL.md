# Development Baseline Protocol

All comparisons use the same 16 frozen development pairs and the receiver logit margin `logit(A) - logit(B)`. Dimensions are reported separately; no weighted composite score is used.

## Message-only

- Whole clean-message rescue is the positive control.
- Attacked-message induction verifies directionality.
- `decision_code` repair is the predeclared field intervention.
- Shuffled attacked messages are the negative control.

## Receiver-only

Each of the 18 frozen receiver sites uses the same paired clean patch, attacked-message bytes, outcome metric, and query accounting as distributed discovery. The best development candidate is descriptive and cannot be selected for validation until method freeze.

## Trace-level counterfactual

The AETHER trace-level counterfactual baseline replays recorded clean or attacked mediator values without internal activations. It is not represented as CAR, DoVer, CASPIAN, or another external method.

## Preliminary distributed comparison

Heterogeneous evidence is represented as sender-internal→message-field, message→outcome, and receiver-internal→outcome relations. A sender and receiver candidate coexisting on development data does not prove one continuous neural circuit. Incremental value must later be assessed on frozen held-out data through recovery, specificity, mechanism size, query count, stability, clean utility, and wall-clock cost.

For every supported internal candidate, the paired-clean self-patch control records clean accuracy before/after, clean margin change, invalid-output rate, and latency. This is an oracle causal diagnostic, not yet a deployable defense or Pareto selection.
